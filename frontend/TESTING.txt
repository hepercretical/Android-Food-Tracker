FOOD TRACKER - ANDROID DEVELOPMENT AND MANUAL TESTING

This frontend is a native Java Android app (Android 8.0/API 26 or newer).
The Java GUI is connected to the bundled USDA SQLite catalog and a persistent
on-device food log. Search foods, enter an amount in grams, select a meal, and
log calories, protein, carbohydrates, and fat. The reference goal is 2,000 kcal.
Each meal supports multiple entries and confirmed removal. Daily totals use
the phone's local date and refresh on resume and at midnight.

ANDROID STUDIO (OPTIONAL)
Install Android Studio separately if you want its layout editor and debugger.
1. Open the frontend directory as a project in Android Studio.
2. Allow Gradle synchronization. Use JDK 17, 21 or 25 as the Gradle JDK under Settings >
   Build, Execution, Deployment > Build Tools > Gradle if necessary.
3. Open app/src/main/res/layout/activity_tracker.xml and choose Design or Split
   to preview the screen. Meal titles are assigned by TrackerGUI when running.
4. Choose FoodTracker_Phone in the device selector and click Run.
   Device Manager can also create and launch additional virtual phones.

VS CODE OR POWERSHELL
In VS Code, use Terminal > Run Task > Android: run on emulator or phone.
Android: build APK builds the installable debug package.
Android: build and lint checks the app's source and Android resources.

From a PowerShell terminal in frontend:
    powershell -NoProfile -ExecutionPolicy Bypass -File .\android.ps1 Doctor
    powershell -NoProfile -ExecutionPolicy Bypass -File .\android.ps1 Build
    powershell -NoProfile -ExecutionPolicy Bypass -File .\android.ps1 Run

Run builds the app, starts the virtual phone when no device is connected, waits
for boot, installs the APK, and opens the app. The emulator is a separate window;
VS Code is used for editing and tasks. Android Studio supplies visual previews
and Android-specific debugging.

PHYSICAL ANDROID PHONE
Enable Developer options and USB debugging on your phone. Connect it to this PC
and approve the phone's debugging prompt. Run the Doctor action to list devices,
then Run to install and launch the app. Some phones need the manufacturer's
Windows USB driver. If multiple devices are connected, select one explicitly:
    powershell -ExecutionPolicy Bypass -File .\android.ps1 Run -DeviceSerial SERIAL

Alternatively, transfer app/build/outputs/apk/debug/app-debug.apk to the phone
and install it, granting permission to install from that transfer app if asked.
This is a debug APK for testing; publication requires a signed release build.

MANUAL CHECKLIST
- Launch on a fresh install: calorie total is 0 / 2,000 kcal with zero macros.
- Search for "apples, fuji" and select the result (58.2 kcal per 100 g).
- Enter 150 grams, choose Lunch, and Log food: expect 87 kcal (rounded),
  protein 0.2 g, carbs 23.6 g, fat 0.2 g. Lunch shows the food and 87.3 kcal.
- Add the same food at 50 grams to Snacks: daily total becomes 116 kcal,
  protein 0.3 g, carbs 31.4 g, fat 0.3 g.
- Use a meal card's Add food button to search directly for that meal.
- Try an empty search, a food name that does not exist, and zero grams.
- Cancel search/portion/removal dialogs: no entries or totals should change.
- Remove one entry and confirm meal and daily totals decrease correctly.
- Close/reopen and rotate the app: saved foods and totals must persist.
- Tap the search field: keyboard appears and the field remains visible.
- Type text, rotate the phone, and confirm Android restores the search text.
- Rotate to landscape: content scrolls and stays clear of system bars.
- Increase system font size: text wraps without hiding the meal controls.
- Confirm meals without entries show the empty state and 0 kcal.

AUTOMATED SQLITE CHECKS (CONNECTED EMULATOR)
From frontend, with ANDROID_HOME and GRADLE_USER_HOME configured:
    .\gradlew.bat assembleDebug assembleDebugAndroidTest lintDebug
    adb install -r app\build\outputs\apk\debug\app-debug.apk
    adb install -r app\build\outputs\apk\androidTest\debug\app-debug-androidTest.apk
    adb shell am instrument -w com.collegediscovery.foodtracker.test/com.collegediscovery.foodtracker.RepositoryTestRunner
The dependency-free test runner verifies real USDA search/macros, calorie-unit
selection, portion scaling, date filtering, invalid inputs, persistence,
removal, and migration from the first food-log schema. It uses a separate cache
database and never changes the application's user log. Look for
ALL REPOSITORY CHECKS PASSED.

TOOLS AND RECOVERY
SDK location: %LOCALAPPDATA%\Android\Sdk
Java: the existing JDK 25, a JDK 17/21 installation, or Android Studio's runtime
Virtual phone: FoodTracker_Phone (Android API 36, standard Android, x86_64)
Build: Android Gradle plugin 9.0.1 with Gradle 9.1.0.

On a new Windows PC, install Android Studio or a JDK (17, 21 or 25), then run:
    powershell -NoProfile -ExecutionPolicy Bypass -File .\android.ps1 Setup
Setup downloads the official SDK tools and packages, displays/accepts their
licenses, creates the virtual phone, and generates the official Gradle wrapper.
Downloads require an internet connection and several GB of free disk space.
Doctor reports emulator acceleration; Windows Hypervisor Platform and firmware
virtualization may need to be enabled if acceleration is unavailable.
