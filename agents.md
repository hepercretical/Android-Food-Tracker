# Project agent guide

## Overview

College Discovery Project is a local-first calorie and macronutrient tracker. The `backend/FoodData.sqlite` file is the USDA FoodData Central source database. The Android app in `frontend/` is the Java UI and application layer.

## Structure

- `backend/FoodData.sqlite`: source food/nutrient data. Do not edit this file by hand.
- `frontend/app/src/main/java/com/collegediscovery/foodtracker/`: Android application classes.
- `frontend/app/src/main/res/`: Android layouts, strings, colors, and drawables.
- Gradle packages `backend/FoodData.sqlite` directly as an Android asset; do not maintain a duplicate copy.

## Architecture

- Keep view binding and presentation code in `*GUI` classes.
- `TrackerController` coordinates search, logging, and lifecycle handling. `Meal`, `Food`, `FoodLogEntry`, and `NutritionSummary` are domain models.
- Keep SQLite access in `FoodRepository`; do not put SQL in Activities or view classes.
- `FoodRepository` owns the on-device database copy and the user food-log table.
- Use background threads for database work, then update views on the Android main thread.
- Store user-entered log data locally. The USDA source data is read-only.
- Nutrient amounts are per 100 grams. Scale by entered grams / 100; never treat kJ as kcal. Prefer kcal nutrient 1008, then specific Atwater 2048, then general Atwater 2047; convert kJ only as a fallback. Do not report missing nutrients as zero.
- Dates are ISO local dates (`yyyy-MM-dd`). Logs must survive rotation and app restarts and be filtered by day.

## Verification

From `frontend/`, use `./gradlew.bat assembleDebug` for a build. The Android app targets API 36 and supports API 26+ with Java 17.
Use `powershell -NoProfile -ExecutionPolicy Bypass -File .\android.ps1 Check` for build/lint, and `Run` to build, install, and launch the existing emulator. VS Code exposes these as Android tasks in `.vscode/tasks.json`. Keep machine SDK paths in ignored `local.properties`.

## Change guidance

- Prefer small, focused classes and resource strings over hard-coded UI text.
- Preserve existing user changes and do not commit generated `frontend/app/build/` output.
- When changing the database schema, update `FoodRepository.DATABASE_VERSION` and provide an upgrade path.
